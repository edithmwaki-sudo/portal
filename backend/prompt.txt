=====================================================================
JWT TOKEN STRATEGY
=====================================================================

Implement a dual-token authentication strategy.

ACCESS TOKEN

Lifetime

20 minutes

Contains

- user id
- username
- role id
- session uuid
- permissions

Permissions must be embedded as an array of permission names.

Example

[
    "student.create",
    "student.update",
    "student.view",
    "finance.receipt.create"
]

Access Tokens are never stored in the database.

REFRESH TOKEN

Lifetime

30 days

Store ONLY the bcrypt hash.

Never store plain refresh tokens.

Never include permissions inside Refresh Tokens.

=====================================================================
REFRESH TOKEN FLOW
=====================================================================

When an Access Token expires

1.

Validate Refresh Token.

2.

Validate session.

3.

Ensure session has not been revoked.

4.

Ensure session has not expired.

5.

Load latest user.

6.

Load latest role.

7.

Load latest permissions.

8.

Generate NEW Access Token.

9.

Generate NEW Refresh Token.

10.

Replace stored Refresh Token hash.

11.

Return new tokens.

Every new Access Token MUST always contain the user's latest permissions.
