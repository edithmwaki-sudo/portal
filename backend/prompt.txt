------------------------------------------------------------
# IMPROVED DATABASE DESIGN
------------------------------------------------------------

The Fees module must follow a reusable template architecture.

A Fee Structure is a reusable template.

It should NEVER be duplicated simply because another course uses the same fee.

Instead, a Fee Structure is assigned to one or many academic contexts through the CourseFeeAssignment table.

This ensures normalization and prevents duplicated fee definitions.

------------------------------------------------------------
## FeeStructure

Represents a reusable fee template.

Examples

- Diploma Regular Fee
- Certificate Fee
- January Intake Fee
- Engineering Fee
- International Students Fee

Fields

- id
- feeName (Unique)
- description (Optional)
- startDate
- endDate
- status (Active/Inactive)
- createdBy
- updatedBy
- createdAt
- updatedAt
- deletedAt (Soft Delete)

Relationships

FeeStructure

hasMany FeeItems

hasMany CourseFeeAssignments

------------------------------------------------------------

# NORMALIZATION RULES

Fee Structures are reusable templates.

Do NOT duplicate a Fee Structure simply because another Course uses it.

Multiple Courses may reference the same Fee Structure.

Only the assignment changes.

------------------------------------------------------------
# UNIQUE CONSTRAINTS

FeeStructure

Unique

feeName

------------------------------------------------------------

CourseFeeAssignment

Unique Composite Index

(
courseId,
curriculumId,
academicYearId,
academicSessionId,

)

Only ONE Active Fee Structure can exist for the same academic context.

------------------------------------------------------------
# BUSINESS RULES

A Fee Structure

• must contain at least one Fee Item.

Fee Item amount

• cannot be negative.

Item Name

• cannot be duplicated within the same Fee Structure.

Deleting a Fee Structure

• is prohibited if Active Course Fee Assignments exist.

Instead

Deactivate it.

Historical records must remain intact.

Fee Structures should never be permanently deleted.

Soft Delete only.

Course Fee Assignments are versioned.

If a Fee changes for the next Academic Year,

Create a NEW Assignment.

Do NOT overwrite previous assignments.

Students already billed must continue referencing the historical Fee Structure.
